0How to use this runbook

Read this whole section before touching anything. It tells the executor (you, the Claude building these in the browser) what you are, what you must not assume, and the one hard constraint about CC360.

Who runs this

A Claude with the Claude-in-Chrome extension driving Austin's own authenticated CC360 browser session. CC360 workflows are UI-only — there is no API to create or edit them (confirmed "under review" in 2026). So every node below is built by clicking through the Workflow builder, not by calling an endpoint.

Hard constraint — confirm first. Before building anything, open app.coursecreator360.com and confirm you can actually see and click the Automation → Workflows builder. If the page will not load for you, STOP and tell Austin — do not fake progress. (The in-app preview browser has historically been blocked here; the Chrome extension on Austin's logged-in session is the supported path.)

Golden rule: the edge functions already fire — opt-ins and scorecard completions already upsert the contact and stamp the trigger tags in CC360. Your job is only the workflow that reacts to those tags. Never rebuild the lead capture; never change the tag names. Build to the tags exactly as written in each workflow's "Trigger" box.

What each workflow spec gives you

  • Trigger — the exact CC360 "Contact Tag" (or calendar) event that starts it. Copy the tag verbatim.
  • Goal — the single outcome that counts as success (used as the workflow Goal / exit).
  • Build steps — the ordered nodes to add, with the config for each.
  • Messages — ready email/SMS copy (brand voice; no the word "free" in customer-facing copy per brand rule).
  • Branches, exit, misfire guards — what to split on, when to stop, and the traps to avoid.

1Pre-flight prerequisites — must pass before building

90% of "the automation misfired" is really one of these not being set. Verify every box. If one fails, fix or flag it before building workflows on top of it, or messages will silently never send.

A · Deliverability (the #1 misfire source)

  • Email sending domain verified in CC360 (Settings → Email Services → Dedicated Domain). Send a live test to a Gmail + an Outlook address and confirm it lands in the inbox, not spam. If unverified, every email node fails silently.
  • From name / from email / reply-to set (e.g. From "BreedWise", reply-to a monitored inbox — support@breedwise.io or the setter's).
  • Physical mailing address + unsubscribe present in the email footer (CAN-SPAM). CC360 adds these via the account business profile — confirm it's filled.
  • SMS A2P 10DLC registered & approved (Settings → Phone Numbers). If pending/declined, every SMS node silently drops — in that case, build the SMS nodes but leave them OFF and note it, or skip them. Do not ship broken SMS.

B · Calendars & the closer

  • A booking calendar exists for discovery/enrollment calls, connected to the closer's real Google/Outlook calendar (so double-booking can't happen).
  • The two Typeforms that route to booking are live and point at that calendar: application/book-a-call MFOGn2eF and the readiness qualifier r44lzVGR.
  • Round-robin / assignment set: one setter today (Regina); closer (Austin) assigned at booking. Add Yasmin to round-robin only when she starts.

C · Tags, fields, pipeline (already created by the edge functions — just confirm they exist)

  • The pipeline "New VSL Funnel" exists with stages: Application Submitted · Qualified - No Booking · Enrollment Call Booked · Lost / No Response · Not Qualified.
  • Custom fields exist: breeding_stage, instagram, lead_score. (Missing a field never blocks the tag — but confirm so nurture can personalize.)
  • The trigger tags listed in each workflow appear under Settings → Tags after one live/test submission. If a tag is missing, the capture hasn't fired yet — do a real test submission first (see §3).

D · Team notification channel

  • Decide the alert channel per funnel: Slack (a webhook already exists and Case-Study opt-ins already post to it from the edge function), internal email to the team, and/or SMS to the setter for hot leads.
  • Have the recipient list ready: setter (Regina), Jennifer, Austin, Dr. Fontaine for litter. Put these in a single "Team — Internal" user/email group so you reference one thing.
Do not duplicate the Slack alert. Case-Study opt-ins already post to Slack from the masterclass-optin edge function. If you also add a Slack node in W1, the team gets two pings per lead. For W1, use internal email/SMS for the team, not Slack — or explicitly replace the edge-function ping (don't run both).

2Global standards — apply to every workflow

Build all six to the same conventions so they're predictable, testable, and never step on each other.

Naming

Workflow name = LM · <Funnel> · <purpose>, e.g. LM · Puppy Content · Nurture + Book. Folder: Lead Magnets. This makes them findable and the self-test reports legible.

Trigger pattern

Trigger = Contact Tag → "tag added" → the exact tag. Add filter Contact → Tag is not lm-<funnel>-done so a re-tag can't re-run a finished contact.

Re-entry / dedup

Workflow settings → Allow re-entry = OFF. First node after trigger: If contact already has lm-<funnel>-active → exit. Last node: remove -active, add -done.

Quiet hours & DND

Enable "Allow sending within business hours only" for SMS (e.g. 8am–8pm lead's timezone). Every send node: skip if DND. Honor unsubscribe/opt-out globally.

Stop-on-reply / stop-on-book

Add a workflow Goal: "Appointment booked" and "Replied to a message." When hit, the contact exits the nurture so they never get "did you forget?" after they already booked or replied.

Team-notify sub-pattern

Reused block: Internal Notification (email + optional SMS to the setter) carrying name, email, phone, source, lead band, and a deep link to the contact. Hot bands notify immediately; cold bands roll up daily.

Qualifier gate before booking — one gate only

Rule: exactly one qualifier between a lead and the calendar. Never stack scorecard + Typeform + calendar questions — three gates kill conversion. Pick the lightest gate that still qualifies, then book.

  • Keep the Typeform qualifier on the high-ticket application calls — W1 Free Case Study (MFOGn2eF), W5 Puppy Content (MFOGn2eF), W6 Litter Blueprint (r44lzVGR). It routes qualified → calendar vs disqualified → downsell, captures breeding stage/budget/timeline for the closer, and lifts show + close rate (worth the friction on a $6k offer).
  • No second form on the scorecards — W2 Profitable Breeder, W3 Healthy Litter, W4 Program. The scorecard is the qualifier (it already scored them and pushed answers into CC360). Send qualified bands straight to the calendar; capture any extra data with CC360 calendar intake questions, not a separate Typeform.
  • On paid/cold traffic, A/B the gate — gated usually wins on qualified calls booked and show-rate even if raw bookings dip.

SMS consent — legacy contacts (one-time gate)

Rule: do not send marketing texts to any contact who opted in on or before Oct 31, 2026 until they re-confirm. Those leads opted in before the consent disclosure ("receive emails & texts · msg/data rates · reply STOP") went live, so their numbers are not consented for marketing SMS. New opt-ins from the updated forms are consented — this gate only applies to the back-catalog. Email to these contacts is unaffected; only SMS is held.

  • Segment: Smart List = created on/before 2026-10-31 AND has phone AND does not have tag sms-consent-confirmed. Tag it sms-legacy.
  • One-time confirmation (email-first): email a short "want texts too?" note whose reply/click adds sms-consent-confirmed. If A2P is approved you may send one confirmation SMS — Reply YES to get texts from BreedWise. Msg & data rates may apply, reply STOP to opt out. A single opt-in prompt is permitted; a marketing blast to this segment is not.
  • Gate every SMS node (all six workflows): add filter send SMS only if tag sms-consent-confirmed OR contact created after 2026-10-31. Old contact with no tag → skip the SMS, keep the email. Nobody is dropped; they just stay email-only until they confirm.
  • STOP / HELP handling stays global (CC360 honors it automatically) and is now documented in the privacy policy.
Timezone: set each contact's timezone from the opt-in (CC360 infers from phone/IP). All "wait until 9am" and reminder offsets use the contact's timezone, not the account's.

The reusable "Internal Team Notification" block (build once, reference in each workflow)

  • Email → Internal to the Team group. Subject: 🔔 New {{contact.source}} lead — {{contact.first_name}} ({band}). Body: all fields + {{contact.profile_url}}.
  • If lead band = hot/qualified → SMS → Internal to the setter: Hot {{source}} lead: {{first_name}} {{phone}}. Call within 10 min.
  • Else → add to a daily digest tag digest-new (a separate once-a-day workflow emails the rolled-up list).

This is two linked workflows: 1A Opt-in nurture (watch the case study → apply) and 1B Application router (qualified vs not → book or downsell).

1A · Opt-in nurture — "watch it, then apply"

Trigger: tag added case study - opted in. (Team Slack alert already fires from the edge function — do not add another.)

  • Internal notify — email the team only (Slack already pinged). One line, link to contact.
  • Email 1 · instant — deliver the case study. Subject "Your case study is inside 👇". Big button to the VSL/case-study page. Set custom field cs_sent=yes.
  • Wait 45 min → If page not visited (no cs_watched) → Email 2 nudge: "Did the link work? Here it is again."
  • Wait to next day 9am → Email 3 — the "is this you?" qualifier email with the Apply button (Typeform MFOGn2eF).
  • SMS · day 1 (if opted in & A2P live) — "Watched the case study? Reply YES and I'll send the next step." (stop-on-reply goal catches replies.)
  • Day 2, Day 4, Day 6 — 3 value emails (objection → proof → urgency), each ending in the Apply button.
  • Goal: tag academy-qualified OR academy-disqualified added → exit 1A (they applied; 1B takes over). Also exit on "appointment booked."

1B · Application router — qualified vs not

Trigger A: tag added academy-qualified. Trigger B: tag added academy-disqualified. (Build as one workflow with a filter, or two — one per tag is cleaner for testing.)

Qualified path

  • Internal notify — HOT: email + SMS the setter immediately ("Call within 10 minutes"). Move opportunity to Qualified - No Booking (the edge fn already created it).
  • Email · instant — "You're a fit — grab your call time." Button = the CC360 calendar (the Typeform already routes here, but re-send in case they bounced).
  • SMS · instant (if live) — "This is Regina with BreedWise — saw your application, you're a great fit. Here's my calendar: {link}".
  • Wait 1 hr → If no booking → reminder email + task for the setter to manually call.
  • Day 1, Day 2, Day 3 → If still no booking → 3 "book your call" nudges, escalating. After day 5 no response → move opportunity to Lost / No Response and exit.
  • Goal: appointment booked → go to 1C Booking (below) and exit.

Disqualified path (TPB downsell)

  • Move opportunity to Not Qualified. No hot alert, no setter SMS.
  • Email · instant — gracious "not a fit right now" + the $291 TPB (The Profitable Breeder) offer link.
  • 3-email TPB nurture over a week. Exit on purchase tag or after the sequence.

1C · Booking confirmation + reminders + no-show (shared by W1/W5)

Trigger: Appointment booked (CC360 calendar). Reused by every funnel that books a call.

  • Move opportunity → Enrollment Call Booked. Internal notify: "Call booked — {name}, {time}" to setter + closer.
  • Instant confirmation email + SMS with date/time, add-to-calendar, and what to bring.
  • Reminders: 24 h before (email+SMS), 1 h before (SMS), 10 min before (SMS).
  • On "appointment status = showed" → thank-you + next-step. On "no-show" → immediate "we missed you, rebook" email+SMS, then one more at +1 day; after that mark Lost / No Response.
  • On cancel/reschedule → stop reminders, re-trigger on the new time.
W1 misfire guards: (1) don't double-Slack (edge fn owns it). (2) Qualified and disqualified are mutually exclusive — add a filter so a mis-tagged contact can't run both. (3) The edge fn removes application-partial/started on completion — don't build nurture that depends on those sticking. (4) Exit 1A the instant either application tag lands, or the lead gets both "apply" nudges and "book" nudges at once.

3Self-test protocol — the executor Claude tests itself

You are not done when a workflow is built. You are done when you have proven each one fires correctly end to end with a test contact and then cleaned up. Run this for every workflow before reporting it live. Never report "done" without a passing test log.

Setup — one reusable test identity

  • Create a test contact with a real inbox you control and (if testing SMS) a real phone: name ZZ Test <funnel>, email zztest+<funnel>@<yourinbox> (the +tag keeps them separate and searchable).
  • Tag it manually with the funnel's trigger tag to simulate a real capture — or, better, do a real submission on the live page so you also prove the capture→tag step.

Per-workflow assertions (tick every one)

  • Enrolled: the contact appears in the workflow's Enrollment History within ~1 min of the tag.
  • Each node executed: walk the contact's execution log — every email/SMS node shows Sent, not Skipped/Error. Investigate any Skipped (usually DND, quiet hours, missing domain, or A2P).
  • Email received & renders: open the actual inbox — subject, personalization tokens resolved (no raw {{first_name}}), links go to the right page, unsubscribe present, not in spam.
  • SMS received (if A2P live): correct text, link works, within quiet hours.
  • Branch correctness: run the test once per band/path (e.g. tag lead-hot vs lead-cold) and confirm it took the right branch each time.
  • Internal alert fired: the team email/SMS arrived with the right fields and the contact deep-link works. Confirm hot vs. digest routing.
  • Booking path: actually book a slot via the Typeform/calendar → confirm 1C fires (stage moves to Enrollment Call Booked, confirmation + reminders scheduled, nurture STOPS).
  • No double-send: re-add the trigger tag → confirm the contact does not re-enter (re-entry OFF / -done guard works).
  • Stop-on-goal: after booking, confirm no further "please book" messages are scheduled.
Master smoke test (run after all 6 built): one test lead through each funnel, back to back. Produce a table: Funnel · Enrolled? · Emails sent/received · SMS · Internal alert · Branch correct · Booking→1C · Re-entry blocked. Every cell must be ✅ or carry a written reason. That table is the deliverable to Austin, not "I built them."
Cleanup — mandatory. After testing: delete every ZZ Test contact and opportunity, remove test tags, and confirm no test record remains in the pipeline or in submissions-admin.html. Leaving test data in skews the dashboards and the reports.
Debugging a "misfire" fast: Skipped email → sending domain unverified or contact unsubscribed. Skipped SMS → A2P not approved or DND. Node never reached → wrong trigger tag spelling, or a filter upstream excluded it. Wrong branch → band tag read incorrectly. Double messages → re-entry ON or two workflows share a trigger. Nothing enrolled → the tag never actually landed (test the capture first).

4Misfire-prevention checklist (consolidated)

  • Sending domain verified; A2P approved (or SMS nodes OFF with a note).
  • Every workflow: re-entry OFF + -active/-done guards + goal-based exit.
  • Triggers use the exact tag strings from each spec — copy, don't retype.
  • Mutually-exclusive paths (qualified/disqualified, bands) filtered so none can run twice.
  • No duplicate team alerts — Case Study Slack is owned by the edge function.
  • Cross-funnel dedup: member scorecards (W4) suppress cold nurtures (W2) for the same contact.
  • Date-anchored reminders for webinars (W6, dated W3), not relative waits.
  • Quiet hours + DND + unsubscribe honored on every send.
  • Correct owner per funnel (Regina / Jennifer / Austin / Dr. Fontaine voice).
  • Stop-on-reply and stop-on-book everywhere a human might respond.
  • Test lead cleaned up; dashboards clean.

5Self-rating & what would make it a 10

8.5
Design & triggers: solid and verified against the live edge functions. Held back from 10 only by things that can't be confirmed from outside the CC360 account.

Why it's strong

  • Every trigger tag, pipeline, deal value, and booking Typeform is pulled from the actual edge-function source — not guessed. The workflows will trigger on real events.
  • Each funnel has team alerts, email+SMS, reminders, and a book-a-call path, with explicit branches and exits.
  • Misfire guards and a real self-test protocol are baked in, so the executor proves it works instead of assuming.

What would make it a 10 (confirm these in the account, then I'll tighten)

  1. Deliverability status — is the CC360 sending domain verified and is A2P 10DLC approved? This decides whether SMS ships now or waits. (Biggest unknown.)
  2. Exact calendar(s) & assignment — the real booking calendar link(s) and whether Academy + Puppy Content + Blueprint share one calendar or each has its own.
  3. Team-notify channel per funnel — Slack vs internal email vs setter SMS, and the exact recipient group.
  4. Existing workflows — are any of these partially built already in CC360? If so, we edit, not duplicate (I can't see the account from here).
  5. Webinar model for W6 — fixed live date vs evergreen just-in-time (changes the whole reminder engine).
  6. Email/SMS copy depth — this runbook gives subjects + structure + key copy; say the word and I'll write every email/SMS in full brand voice, ready to paste.
Honest scope note: I built the blueprint the browser-Claude executes — I can't create CC360 workflows directly (UI-only, no API) and I can't see inside the account, so the final 1.5 points are confirmation + live-account tightening, which happen during the build + self-test, not before it.
