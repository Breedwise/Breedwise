The TPB → BOSS Machine

One page for the whole funnel: how a cold social lead becomes a TPB member and then a BOSS implementation client, what the automation does at each step, and what still has to be wired. CC360 (GoHighLevel LeadConnector) is the system of record. Every stage below is one event sent to the tpb-boss-router edge function.

The operating principle

The router owns the logic. CC360 workflows only send messages. Every tool opt-in, completion, booking, and purchase calls one deterministic router that upserts the contact, sets and clears tags, and creates or advances the opportunity. Native CC360 workflows shrink to a single job: tag fires, message sends.

Pipeline: Tool → TPB → BOSS. Setter is Regina across the cold and TPB phase. Closer is Austin from BOSS Opportunity onward. Each card shows the router event, the tags it sets or clears, the resulting pipeline stage, the owner, and the message CC360 fires off that tag.

The two automation layers

Everything above is split across exactly two layers. Keep them separate: logic lives in the router, sending lives in CC360. The full event contract and the per-tool call snippets live in the companion files.

Layer 1 · Edge function

tpb-boss-router

Supabase edge function. Every tool and webhook POSTs one event to it. Deterministic, no AI in the path.
  • Upserts the contact by email or phone against the LeadConnector v2 API, recovering the id on a duplicate so returning leads get re-tagged, never a 400.
  • Sets and clears tags per the event (POST and DELETE-with-body on /contacts/{id}/tags). This is how every kill-switch and no-answer cleanup fires.
  • Creates or advances the opportunity: looks up the Tool → TPB → BOSS pipeline by exact name, finds the opp by contact_id, then PUTs the new stage, value, and status. This stage-move helper does not exist in the codebase yet and is the core new build.
  • Sends the speed-to-lead alert and opens the +15 min setter task on opt-in and completion.
  • Logs every event to tool_submissions and runs Close mirror / Slack / CAPI in the background via EdgeRuntime.waitUntil so intake returns fast.
Layer 2 · CC360 native

Thin tag → send workflows

One job each. A tag the router sets fires a message. No branching logic lives here.
  • tool-lead → optin-email-1 and SMS S1.

  • call-booked → booking-confirm and the reminder sequence.
  • call-noshow → noshow-rebook SMS S8 with rebook link.
  • tpb-member → tpb-welcome and onboarding.
  • boss-opportunity → boss-invite and the book-BOSS-call task.
  • boss-member → boss-welcome and fulfillment handoff.
  • The five opt-in nurture emails already exist as HTML (tpb-tool-email-1 through 5). Load them as CC360 templates, do not rebuild the logic.

Go-live checklist

Run in order. The orchestrator reviews and deploys. This page does not push or deploy anything.

  1. Push the HTML pages to main

    Ship this map, the automation spec, and the router usage notes to review.breedwise.io (GitHub Pages, main branch, repo root). Compile-check every inline script first: one SyntaxError kills the whole page.

    git add tpb-boss-funnel-map.html tpb-boss-automation-spec.html tpb-boss-router-usage.txt git commit -m "TPB -> BOSS master funnel map + automation spec" git push origin main
  2. Deploy the tpb-boss-router edge function

    New Deno function at supabase/functions/tpb-boss-router/index.ts. Copy the CC360 patterns from vsl-apply and partial-capture, and build the new find-opp-then-PUT stage-move helper.

    supabase functions deploy tpb-boss-router --project-ref xhjdowbnqcsvhtcccuqx --no-verify-jwt
  3. Confirm CC360 env, and leave ROUTER_SECRET unset at launch

    CC360_TOKEN, CC360_LOCATION, SUPABASE_URL, and SUPABASE_SERVICE_ROLE_KEY must already be present for the function to upsert, tag, and log. Leave ROUTER_SECRET unset at go-live: when it is unset the router skips the secret check, and every documented caller omits the secret, so setting it now would reject every call. Set it later only once every caller is updated to send the matching x-router-secret header.

    supabase secrets set CC360_TOKEN=... CC360_LOCATION=... --project-ref xhjdowbnqcsvhtcccuqx # Do NOT set ROUTER_SECRET yet. Only after every caller sends x-router-secret: # supabase secrets set ROUTER_SECRET=<long-random-string> --project-ref xhjdowbnqcsvhtcccuqx
  4. Build the CC360 pipeline, stages, and message templates

    Create the Tool → TPB → BOSS pipeline with the nine stages exactly as named: Tool Opt-in, Tool Completed, Setter Working, Connected / Qualified, TPB Member, BOSS Opportunity, BOSS Member, Nurture, Not a Fit. Build the thin tag → send workflows from Layer 2 and load the five tpb-tool-email templates. Resolve the owner tag to a single setter (owner-regina): update program-scorecard, which currently sets owner-jennifer.

  5. Point every funnel page and edge function at the router

    Add the universal tags and the router call to each tool: pb-scorecard, vet-optin, program-scorecard, litter-snapshot, niche-finder, value-architect send tool-optin and tool-complete; stripe-webhook maps product → tpb-purchase / boss-purchase; booking-notify and the calendar / close-events send call-booked and call-noshow. Each tool fires tool-lead and tool-completed so one router path serves all of them. Treat tpb-lead as an alias of tool-lead.

    Open gaps to close here: purchase won events (tpb-member, boss-member) fire nowhere today; the BOSS qualification rule is undefined in code; call-booked / no-show / no-answer are manual; and tool opt-ins do not yet persist fbp / fbc / event_id for CAPI matching.
  6. Test one lead end to end

    Run a single real contact through tool-optin → tool-complete → call-booked → tpb-purchase → boss-qualified → boss-purchase. Confirm at each step: the contact is tagged and un-tagged correctly, the opportunity sits on the right stage at the right value, status flips to won at TPB and at BOSS, and exactly one message fires per tag.
