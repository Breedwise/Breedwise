TPB → BOSS Thin Wiring Spec

The router edge function now owns every decision: tags, stage moves, opportunity value, owner, and the speed to lead notification. That means CC360 is no longer the brain. It is only the mouth and the clock. This page is the API first replacement for the older five workflow build.

Replaces tool-funnel-workflows.html. That page described five CC360 workflows that each created and advanced opportunities, assigned owners, and set stages by hand. All of that logic has moved into the tpb-boss-router edge function. The CC360 workflows below are the thin remainder: send a message, wait, maybe send another. Build from this page, not the old one.

Who owns what

Every tool opt in, completion, booking, and purchase calls the tpb-boss-router edge function. The router does the deterministic work. CC360 reacts to the tags the router sets and does only the two things an edge function cannot: send branded drip messages and wait real world days.

Handled automatically · tpb-boss-router

Nobody wires this in CC360

The edge function calls the LeadConnector v2 API directly for all of it. Do not rebuild any of this as a CC360 workflow.

  • Tags. Sets and removes every tag in the routing contract (contact upsert then tags POST / tags DELETE with body).
  • Opportunity. Creates the opportunity on opt in, then finds it by contact id and advances the stage on every later event (search by contact id, then PUT the stage and value).
  • Stage. Moves the opportunity to the exact stage name for each event.
  • Value. Sets monetary value: 291 through the TPB phase, 3000 at BOSS, 0 on Not a Fit.
  • Owner. Sets the owner tag: owner-regina for the cold and TPB phase, flips to Austin at BOSS.
  • Notify. Fires the speed to lead Slack alert and creates the plus 15 minute setter task. This is the biggest lever, so it lives in code, not in a drip.
  • Logging and attribution. Writes tool_submissions and persists fbp / fbc / event_id so later CAPI events dedupe.
Still required · CC360 native

The thin remainder

Each workflow below is only: trigger on a tag the router set, then send email or SMS or wait N days, then maybe one more step. No stage moves, no opportunity edits, no owner assignment, no task creation. Those are already done.

  • Message delivery. The branded email and SMS drips keyed to each router tag.
  • Time delayed waits. The multi day nurture gaps and the BOSS ascension clock, because an edge function cannot sleep for days.
  • Two tag actions that are themselves time delayed: adding tool-nurture-monthly at the end of the opt in drip, and the webhook callback to the router after the ascension wait. Everything else that touches a tag stays in the router.
  • Exit goals. Standard CC360 workflow goals that pull a contact out of every cold drip the instant they convert or opt out.

CC360 native workflows to build

Seven thin workflows plus one exit convention. Each trigger tag is set by the router, so none of these fire until the router has already set the stage, value, owner, and notification. Bracketed asset names map to the templates in the prerequisites checklist.

On the Nurture stage. The Nurture pipeline stage exists for leads the setter parks at the end of the no-answer cadence, but no router event moves an opportunity into it. That stage move is handled CC360-side or manually, so do not expect a router event to target it.
EXIT

Kill-switch convention (not a standalone workflow)

Applies toCC-1, CC-2, CC-3, CC-4, CC-8 (every cold or nurture drip)
  1. Add these as workflow Goals on each drip above: tag tpb-member OR boss-member OR not-a-fit OR unsubscribed added → remove from workflow.
  2. No stage move or lost reason is needed here. The router already sets the stage (TPB Member, BOSS Member, or Not a Fit) and the lost reason when it sets those tags.
Purpose   Guarantees the cold sequences stop the instant someone converts or opts out, without a separate workflow carrying any logic. Opt outs use unsubscribed (no stage move). not-a-fit is the setter or router disqualify path.

Prerequisites in CC360

The router looks pipelines and stages up by exact name. These must exist, spelled exactly, before the router can advance anything.

  • Pipeline: create Tool → TPB → BOSS with these nine stages, exact names and order: Tool Opt-in, Tool Completed, Setter Working, Connected / Qualified, TPB Member, BOSS Opportunity, BOSS Member, Nurture, Not a Fit.
  • Keep separate: the existing New VSL Funnel pipeline stays as is. It is the Academy funnel (6000 / 291), adjacent to this one. Do not merge them.
  • Email templates to create: optin-email-1 to optin-email-5 (load from the existing tpb-tool-email-1 through tpb-tool-email-5 HTML), booking-confirm, noshow-rebook, tpb-welcome, the three BOSS ascension emails (tpb-boss-ascension-email-1.html, tpb-boss-ascension-email-2.html, tpb-boss-ascension-email-3.html, loaded into CC-5), boss-invite, boss-welcome, and the monthly nurture email. Swap the placeholders [RESULT_LINK], [BOOK_CALL_LINK], [TPB_LINK], [BOSS_INFO_LINK], [BOOK_BOSS_CALL_LINK].
  • SMS templates to create: S1 (results ready), S2 (finish your tool), S3 (top 3 moves), S4.1 to S4.4 (no-answer cadence), S8 (no-show rebook), plus the booking and BOSS reminder texts. Include Reply STOP to opt out on the first text.
  • Sending setup: provision the SMS number, set the booking calendar behind [BOOK_CALL_LINK], create the owner users Regina (setter) and Austin (closer) and their notification channels.
  • Router callback: whitelist and test the webhook action to https://xhjdowbnqcsvhtcccuqx.supabase.co/functions/v1/tpb-boss-router used by CC-5.
  • Honor DND and quiet hours on all SMS.
